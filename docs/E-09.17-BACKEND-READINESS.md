# Backend Readiness Specification — Phase E-09.17: Platform Support Desk, Customer Success and Tenant Assistance Governance

> **STATUS**: PROPOSED ARCHITECTURAL SPECIFICATION FOR FUTURE IMPLEMENTATION.  
> **CURRENT REPOSITORY STATE**: Verified frontend contracts, typed domain models, evaluator engine, deterministic fixtures, and local state adapters inside `dashboard/`.

## 1. Domain Entities & Database Persistence Schema

The future persistence layer must establish relational tables with strong foreign keys, index coverage, and optimistic concurrency locking.

### 1.1 Support Tickets (`support_tickets`)

```sql
CREATE TABLE support_tickets (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ticket_number VARCHAR(32) NOT NULL UNIQUE, -- e.g., TCK-2026-1001
    organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE RESTRICT,
    subject VARCHAR(255) NOT NULL,
    description TEXT NOT NULL,
    category VARCHAR(64) NOT NULL,
    priority VARCHAR(16) NOT NULL CHECK (priority IN ('low', 'normal', 'high', 'urgent')),
    status VARCHAR(32) NOT NULL CHECK (status IN ('new', 'open', 'in_progress', 'awaiting_tenant', 'awaiting_internal', 'escalated', 'resolved', 'closed')),
    source VARCHAR(32) NOT NULL DEFAULT 'portal',
    assigned_operator_id UUID REFERENCES platform_users(id) ON DELETE SET NULL,
    assigned_team_id VARCHAR(64) NOT NULL DEFAULT 'team_tier1',
    sla_policy_id UUID REFERENCES sla_policies(id) ON DELETE SET NULL,
    sla_state VARCHAR(32) NOT NULL DEFAULT 'unknown',
    
    -- Requester snapshot (School Admin / Staff)
    requester_name VARCHAR(128) NOT NULL,
    requester_email VARCHAR(255) NOT NULL,
    requester_role_title VARCHAR(128) NOT NULL,
    requester_user_id UUID, -- Optional link to tenant user record
    
    -- Escalation details
    is_escalated BOOLEAN NOT NULL DEFAULT FALSE,
    escalated_at TIMESTAMPTZ,
    escalated_by UUID REFERENCES platform_users(id),
    escalation_reason TEXT,
    escalation_tier VARCHAR(64),
    
    -- Timestamps & SLA markers
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    first_response_at TIMESTAMPTZ,
    resolved_at TIMESTAMPTZ,
    closed_at TIMESTAMPTZ,
    
    -- Concurrency control
    lock_version INTEGER NOT NULL DEFAULT 1
);

CREATE INDEX idx_tickets_org_id ON support_tickets(organization_id);
CREATE INDEX idx_tickets_status ON support_tickets(status);
CREATE INDEX idx_tickets_priority ON support_tickets(priority);
CREATE INDEX idx_tickets_assigned_operator ON support_tickets(assigned_operator_id);
CREATE INDEX idx_tickets_assigned_team ON support_tickets(assigned_team_id);
CREATE INDEX idx_tickets_created_at ON support_tickets(created_at DESC);
```

### 1.2 Ticket Timeline Messages (`ticket_messages`)

```sql
CREATE TABLE ticket_messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    ticket_id UUID NOT NULL REFERENCES support_tickets(id) ON DELETE CASCADE,
    type VARCHAR(32) NOT NULL CHECK (type IN ('internal_note', 'tenant_reply', 'system_event')),
    author_id UUID NOT NULL, -- Platform user ID or Tenant user ID
    author_name VARCHAR(128) NOT NULL,
    author_role VARCHAR(64) NOT NULL,
    content TEXT NOT NULL,
    is_draft BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_ticket_messages_ticket_id ON ticket_messages(ticket_id, created_at ASC);
```

### 1.3 Service-Level Agreement Policies (`sla_policies`)

```sql
CREATE TABLE sla_policies (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(128) NOT NULL,
    description TEXT,
    plan_tier VARCHAR(64) NOT NULL DEFAULT 'all',
    applicable_categories JSONB NOT NULL DEFAULT '"all"',
    applicable_priorities JSONB NOT NULL,
    first_response_target_minutes JSONB NOT NULL,
    resolution_target_minutes JSONB NOT NULL,
    business_hours_enabled BOOLEAN NOT NULL DEFAULT FALSE,
    business_hours_start TIME,
    business_hours_end TIME,
    business_hours_timezone VARCHAR(64) DEFAULT 'UTC',
    business_days INTEGER[] DEFAULT '{1,2,3,4,5}',
    is_enabled BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 1.4 Customer Success Tasks (`customer_success_tasks`)

```sql
CREATE TABLE customer_success_tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255) NOT NULL,
    description TEXT NOT NULL,
    organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    assigned_owner_id UUID NOT NULL REFERENCES platform_users(id) ON DELETE RESTRICT,
    priority VARCHAR(16) NOT NULL DEFAULT 'normal',
    status VARCHAR(32) NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'in_progress', 'completed', 'cancelled')),
    due_date DATE NOT NULL,
    related_ticket_id UUID REFERENCES support_tickets(id) ON DELETE SET NULL,
    completed_at TIMESTAMPTZ,
    completion_notes TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_cs_tasks_org ON customer_success_tasks(organization_id);
CREATE INDEX idx_cs_tasks_due ON customer_success_tasks(due_date ASC) WHERE status != 'completed';
```

## 2. Multi-Tenant Isolation & Access Control

1. **Row-Level Security (RLS)**:
   - Super-Admins in `dashboard/` have cross-tenant read/write permissions governed by platform IAM roles (`SUPER_ADMIN`, `SUPPORT_LEAD`, `SUPPORT_OPERATOR`).
   - Tenant administrators in `tenant-dashboard/` can ONLY query tickets where `organization_id = auth.current_tenant_id()`.
   - Tenant users must NEVER have access to messages where `type = 'internal_note'`.
2. **Strict Internal Note Redaction**:
   - Database queries serving tenant APIs must enforce a hard database-level filter `WHERE type != 'internal_note'`.
   - GraphQL/REST API response serializers must completely strip internal note fields from tenant payloads.

---

## 3. SLA Evaluation Engine & Business Calendars

1. **Background SLA Scheduler Worker**:
   - A Redis/BullMQ background worker must execute every 60 seconds to evaluate open tickets against active SLA policies.
   - Transitions tickets to `approaching_target` at 75% elapsed duration.
   - Marks tickets as `breached` upon target overrun and pushes an event to the notification bus.
2. **Business Hours & Holiday Calendars**:
   - Business calendar calculation must account for the school's configured time zone (e.g. `Africa/Lagos`, `UTC+1`).
   - Non-working hours and declared public holidays must suspend the active SLA timer.
   - Status `awaiting_tenant` pauses the SLA clock; the backend must record `paused_intervals` to subtract tenant-waiting duration from net resolution time.

## 4. Secure Attachment Handling (Future Enhancement)

When ticket file attachments are supported in future phases:
1. **Direct-to-S3 Pre-signed Uploads**:
   - The browser requests a pre-signed PUT URL with a 15-minute expiration.
   - Uploaded files are quarantined in a private bucket (`s3://sms-support-quarantine/`).
2. **Asynchronous Virus & Malware Scanning**:
   - An AWS Lambda / Cloud Run worker runs ClamAV scanning on every uploaded file.
   - Only clean files are moved to the permanent bucket (`s3://sms-support-attachments/`).
3. **MIME & Extension Allowlists**:
   - Permitted: `.png`, `.jpg`, `.jpeg`, `.pdf`, `.txt`, `.csv`, `.log`.
   - Strictly Prohibited: `.exe`, `.sh`, `.bat`, `.js`, `.zip`, `.html`.
   - Size limit: 10 MB per file, max 5 files per message.

## 5. Notification & Dispatch Integration (Phase E-09.16 Linkage)

Support ticket events must publish structured events to the platform notification queue:
1. `TICKET_ASSIGNED`: Dispatches internal notification to assigned operator via email/in-app.
2. `TICKET_ESCALATED`: Dispatches high-priority alert to the escalation team lead.
3. `TICKET_RESOLVED`: Sends resolution email to school requester with an embedded 1-click CSAT feedback link.
4. `SLA_BREACH_WARNING`: Sends operational alert to Slack/Teams webhook and Super-Admin dashboard.

## 6. Audit Logging & Compliance Persistence

All mutations must append to the immutable audit store (`audit_events` from E-09.13):
- Mandatory audit actions: `SUPPORT_TICKET_CREATED`, `SUPPORT_TICKET_STATUS_CHANGED`, `SUPPORT_TICKET_ASSIGNED`, `SUPPORT_TICKET_ESCALATED`, `SLA_POLICY_CREATED`, `CUSTOMER_SUCCESS_TASK_CREATED`, `CSAT_FEEDBACK_SUBMITTED`.
- Metadata must capture `actor_id`, `client_ip`, `target_entity: 'SupportTicket'`, and old/new state diffs.

---

## 7. Search, Cursor Pagination & Concurrency

1. **Full-Text Search**:
   - PostgreSQL `tsvector` column indexing `subject`, `description`, and `ticket_number`.
   - Optional Elasticsearch/OpenSearch ingestion for multi-lingual search across Knowledge Base articles.
2. **Cursor-Based Pagination**:
   - API endpoints (`GET /api/v1/support/tickets`) must support cursor pagination (`limit=50&after=cursor`) for responsive infinite scrolling and high-volume school support operations.
3. **Optimistic Locking**:
   - Every ticket update must pass the expected `lock_version`. If a concurrent operator modified the ticket, return HTTP `409 Conflict` with the latest record to prevent overwriting updates.
