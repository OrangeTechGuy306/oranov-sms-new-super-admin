## 2. Mandatory Backend Requirements

### 2.1 Tenant Creation & Lifecycle State Persistence
1. **Transactional State Machine:** Organization status transitions (`draft`, `pending`, `active`, `suspended`, `inactive`, `archived`) must be executed as atomic ACID transactions.
2. **Justification Enforcement:** Transitions to `suspended` and `archived` must reject requests that lack a mandatory justification string (minimum 5 characters) at the database constraint level or controller validation layer.
3. **Optimistic Locking & Concurrency Control:**
   - Every organization record must carry a version integer (`version: number`).
   - Mutations must execute with `WHERE id = $id AND version = $expected_version`.
   - Concurrent conflicting status updates must reject with HTTP `409 Conflict`.
4. **Idempotency Keys:** Organization creation and simulated provisioning must require an `Idempotency-Key: UUIDv4` header to prevent double-creation under transient network failures.

### 2.2 Organization & Campus Relational Hierarchy
1. **Referential Integrity:** Campuses must have a foreign key `organization_id REFERENCES organizations(id) ON DELETE RESTRICT`. An organization cannot be deleted while campuses remain linked.
2. **Campus Code Uniqueness:** A database unique constraint must enforce `UNIQUE (organization_id, code)` to guarantee that campus codes are unique within the tenant while allowing distinct schools to share standard codes (`MAIN`, `NORTH`).
3. **Single Main Campus Invariant:**
   - Implemented via a conditional partial unique index in PostgreSQL:
     ```sql
     CREATE UNIQUE INDEX idx_single_main_campus_per_org 
     ON campuses (organization_id) 
     WHERE (is_main_campus = true);
     ```
   - Transactional promotion of a campus to main campus must execute atomically:
     ```sql
     BEGIN;
     UPDATE campuses SET is_main_campus = false WHERE organization_id = $org_id;
     UPDATE campuses SET is_main_campus = true WHERE id = $campus_id AND organization_id = $org_id;
     COMMIT;
     ```
4. **Main Campus Deletion Guard:** The backend must reject requests to delete a designated main campus if other campuses exist for that organization (`422 Unprocessable Entity`).

### 2.3 Tenant Isolation & Authorization Boundary
1. **Zero Cross-Tenant Leakage:** All tenant database queries must enforce tenant separation. When using a shared database with PostgreSQL Row-Level Security (RLS), the connection pool session must execute `SET LOCAL app.current_tenant_id = $tenant_id` on every query transaction.
2. **Super-Admin RBAC:** Only authenticated identities holding `super_admin`, `platform_manager`, or `support_lead` platform claims in cryptographically signed JWT tokens are permitted to mutate organization lifecycle states or campus quotas.
3. **Suspension Enforcement:** When an organization is placed in `suspended` or `archived` state, the auth token gateway must immediately reject subsequent tenant user sessions with `403 Forbidden` (`TENANT_SUSPENDED`), while preserving platform Super-Admin inspection access.

### 2.4 Subscription Quota & Module Entitlement Enforcement
1. **Campus Quota Gatekeeper:** Before committing a new campus record, the backend must verify that the organization's active campus count does not exceed the plan tier's `maxCampuses` quota.
2. **Canonical Module Entitlement Evaluation:** The backend must replicate the Phase E-09.6 deterministic 7-tier precedence evaluation engine (`platform_disabled` > `missing_dependencies` > `org_force_disable` > `org_force_enable` > `tier_included` > `addon_license` > `default_denied`).
3. **Acyclic Dependency Enforcement:** Server-side dependency checks must reject module activation requests that violate dependency graphs or introduce circular prerequisites.

### 2.5 Real Provisioning Pipeline & Saga Orchestration
When transitioning from the Phase E-09.7 frontend simulation to real cloud infrastructure provisioning, the backend must implement a durable **Saga / Workflow Orchestrator** (e.g., Temporal, AWS Step Functions, or BullMQ with transactional outbox):

| Stage | Action | Failure Compensation / Rollback |
|---|---|---|
| **1. DNS & Ingress** | Reserve subdomain in Cloudflare/Route53 edge router | Release subdomain lease |
| **2. Storage & Isolation** | Provision isolated tenant schema or RLS partition | Drop created tenant partition |
| **3. Seed Baseline** | Insert initial campus, academic year, and system roles | Truncate tenant baseline tables |
| **4. Entitlement Sync** | Clone canonical plan module catalog and initial overrides | Purge tenant entitlement records |
| **5. Welcome Dispatch** | Queue administrative activation email with reset link | Invalidate activation token |

### 2.6 Server-Side Auditing & Immutability
1. **Append-Only Ledger:** All lifecycle events, campus additions/modifications, module overrides, and provisioning actions must write to an append-only `platform_audit_logs` table.
2. **Cryptographic Chaining (Optional/Recommended):** Compute SHA-256 hashes linking each log entry to the preceding entry hash to provide tamper-evident compliance logs.
3. **Actor Context:** Capture `actor_id`, `actor_role`, `ip_address`, `user_agent`, `target_organization_id`, `action_type`, `payload_before`, `payload_after`, and `justification_reason`.

## 3. Recommended API Endpoint Specifications

All endpoints require `Authorization: Bearer <JWT>` and platform admin privileges.

### 3.1 Organization Lifecycle Endpoints

#### `PATCH /api/v1/platform/organizations/:id/lifecycle-status`
Updates an organization's lifecycle status subject to state machine rules.

- **Request Body:**
```json
{
  "requestedStatus": "suspended",
  "reason": "Outstanding invoice overdue by 45 days. Account delinquent.",
  "expectedVersion": 3
}
```
- **Responses:**
  - `200 OK`: Updated organization record with incremented version.
  - `400 Bad Request`: Reason missing or under 5 characters.
  - `409 Conflict`: `expectedVersion` mismatch (concurrent update detected).
  - `422 Unprocessable Entity`: Illegal transition (e.g. `draft` ➔ `active`).

#### `GET /api/v1/platform/organizations/:id/readiness`
Evaluates and returns the authoritative 8-item configuration readiness score.

- **Response 200 OK:**
```json
{
  "score": 85,
  "status": "needs_attention",
  "blockerCount": 0,
  "attentionCount": 1,
  "items": [
    {
      "id": "campuses_registered",
      "category": "campuses",
      "status": "complete",
      "message": "2 campus(es) registered with designated main campus.",
      "isBlocker": true
    },
    {
      "id": "technical_regional",
      "category": "technical",
      "status": "incomplete",
      "message": "Regional timezone or primary locale not configured.",
      "isBlocker": false
    }
  ]
}
```

### 3.2 Multi-Campus Endpoints

#### `GET /api/v1/platform/organizations/:id/campuses`
Returns list of campuses for the specified organization.

- **Response 200 OK:**
```json
{
  "data": [
    {
      "id": "cmp_001_1",
      "organizationId": "org_001",
      "name": "Oak Hill Main Campus",
      "code": "MAIN",
      "isMainCampus": true,
      "type": "main",
      "status": "active",
      "address": {
        "street": "100 Academy Drive",
        "city": "Boston",
        "stateOrProvince": "MA",
        "country": "United States",
        "postalCode": "02108"
      },
      "studentCapacity": 1500,
      "createdAt": "2025-08-15T09:00:00Z",
      "updatedAt": "2026-03-12T14:22:00Z"
    }
  ]
}
```

#### `POST /api/v1/platform/organizations/:id/campuses`
Creates a new campus for an organization.

- **Request Body:**
```json
{
  "name": "Oak Hill STEM & Innovation Hub",
  "code": "STEM-HUB",
  "type": "specialized",
  "isMainCampus": false,
  "address": {
    "street": "250 Innovation Way",
    "city": "Cambridge",
    "stateOrProvince": "MA",
    "country": "United States",
    "postalCode": "02142"
  },
  "studentCapacity": 400
}
```
- **Responses:**
  - `201 Created`: Created campus object.
  - `400 Bad Request`: Code contains invalid characters.
  - `409 Conflict`: Campus code already in use within this organization.
  - `403 Forbidden`: Organization has reached its subscription plan campus limit.

#### `PUT /api/v1/platform/organizations/:id/campuses/:campusId/designate-main`
Atomically promotes a campus to main campus.

- **Response 200 OK:** Returns updated campus array with single main campus designated.

## 5. Security, Privacy & Compliance Controls

1. **FERPA / GDPR Compliance:**
   - Multi-tenant database partitioning must guarantee that student academic, disciplinary, and personally identifiable information (PII) is inaccessible across tenant boundaries.
   - Tenant deletion/archival workflows must adhere to jurisdictional data retention policies (e.g. 7-year student transcript preservation).
2. **Secrets & Credentials Management:**
   - Database credentials, SMTP secrets, and Cloudflare API keys must be injected via runtime secret vaults (e.g. AWS Secrets Manager, HashiCorp Vault).
   - Zero hardcoded secrets in repositories or client bundles.
3. **Rate Limiting & Abuse Prevention:**
   - Platform Super-Admin APIs must enforce IP-based and user-based token bucket rate limiting (e.g. 100 requests per minute).
   - Subdomain reservation checks must enforce anti-squatting filters blocking trademarked or reserved names (`admin`, `api`, `auth`, `app`, `billing`).
