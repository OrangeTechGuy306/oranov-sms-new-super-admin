## 1. Domain Entities & Database Persistence Architecture

To transition from client-side memory fixtures to high-performance platform BI, the backend architecture must establish dedicated transactional event stores and aggregated rollups.

### 1.1 Analytics Snapshots Table (`platform_analytics_snapshots`)

```sql
CREATE TABLE platform_analytics_snapshots (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    snapshot_date DATE NOT NULL,
    snapshot_granularity VARCHAR(16) NOT NULL CHECK (snapshot_granularity IN ('hourly', 'daily', 'weekly', 'monthly')),
    domain VARCHAR(32) NOT NULL CHECK (domain IN ('executive', 'tenants', 'monetization', 'modules', 'support', 'operations', 'communications', 'governance')),
    
    -- Dimensional scoping
    organization_id UUID REFERENCES organizations(id) ON DELETE CASCADE,
    plan_id VARCHAR(64),
    currency VARCHAR(8) NOT NULL DEFAULT 'USD',
    
    -- Aggregate metric payload
    metrics_payload JSONB NOT NULL,
    
    -- Telemetry provenance
    source_status VARCHAR(32) NOT NULL DEFAULT 'verified_production',
    calculated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    calculation_duration_ms INTEGER,
    
    -- Partitioning key
    CONSTRAINT uq_snapshot_interval UNIQUE (snapshot_date, snapshot_granularity, domain, organization_id, plan_id, currency)
);

CREATE INDEX idx_analytics_snapshots_date ON platform_analytics_snapshots(snapshot_date DESC);
CREATE INDEX idx_analytics_snapshots_domain ON platform_analytics_snapshots(domain);
CREATE INDEX idx_analytics_snapshots_org ON platform_analytics_snapshots(organization_id);
CREATE INDEX idx_analytics_snapshots_payload_gin ON platform_analytics_snapshots USING GIN (metrics_payload);
```

### 1.2 Tenant Lifecycle State History (`organization_lifecycle_transitions`)

To enable true historical cohort analysis rather than current-state back-projection:

```sql
CREATE TABLE organization_lifecycle_transitions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    previous_status VARCHAR(32) NOT NULL,
    new_status VARCHAR(32) NOT NULL,
    transition_reason TEXT,
    initiated_by_user_id UUID REFERENCES platform_users(id),
    occurred_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_org_lifecycle_history ON organization_lifecycle_transitions(organization_id, occurred_at);
```

### 1.3 Module Enablement Event Stream (`tenant_module_audit_events`)

```sql
CREATE TABLE tenant_module_audit_events (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    module_id VARCHAR(64) NOT NULL,
    action VARCHAR(32) NOT NULL CHECK (action IN ('enabled_by_plan', 'disabled_by_plan', 'override_force_enabled', 'override_force_disabled', 'override_cleared')),
    actor_user_id UUID REFERENCES platform_users(id),
    occurred_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_module_audit_org ON tenant_module_audit_events(organization_id, module_id);
```

## 2. Metric Ownership & Analytical Calculation Boundaries

To prevent metric drift between dashboard views and external audits:
1. **Source of Truth**:
   - Financial metrics (MRR, ARR, ARPU, Receivables) must be calculated by the Billing & Ledger Service, which guarantees double-entry reconciliation against actual payment provider transactions.
   - Support SLA metrics must be calculated by the Support Desk Event Worker upon ticket state transitions.
   - Module adoption must be evaluated via the Entitlement Engine based on active subscription tier and explicit organization overrides.
2. **Deterministic Rounding Standards**:
   - Currency totals: `Math.round(val * 100) / 100` (2 decimal places).
   - Percentages: `Math.round(val * 10) / 10` (1 decimal place).
   - Time durations: Exact integer minutes.
3. **Coercive Zero Prohibition**:
   - Missing observations or unconfigured telemetry MUST return `null` or explicit status codes (`unavailable`, `not_connected`). The backend must never convert unrecorded latency or missing backups to `0`.

## 3. High-Volume Pagination & Aggregation Strategies

As the multi-tenant SaaS platform scales beyond 10,000 schools:
1. **Materialized Aggregation Views**:
   - Precompute daily and monthly rollups using PostgreSQL Materialized Views or ClickHouse analytical tables.
   - Executive dashboard queries must hit pre-aggregated snapshots (`platform_analytics_snapshots`) with sub-50ms latency rather than doing full table scans over `organizations` or `audit_events`.
2. **Cursor-Based Ledger Pagination**:
   - Detailed tabular reports (e.g., all support tickets, all audit events) must use keyset/cursor pagination (`WHERE id > :last_id LIMIT 100`) to maintain deterministic retrieval performance.
3. **Background Asynchronous Report Generation**:
   - For report exports containing > 5,000 rows, the backend must initiate an asynchronous worker job (`analytics_export_queue`). The API returns `202 Accepted` with a job tracking URL. Once complete, a secure, time-limited presigned S3 download link is generated.

## 4. Multi-Tenant Isolation & Least-Privilege Authorization

1. **Super-Admin Scoping**:
   - Access to `/analytics` requires platform-level administrative credentials (`super_admin`, `platform_auditor`, `finance_admin`).
   - Tenant-level administrators (`school_admin`, `teacher`) must never be granted access to cross-tenant platform BI endpoints.
2. **Data Minimization & Zero-PII Enforcement**:
   - Analytical export payloads must enforce field projection whitelists at the SQL layer.
   - Student, guardian, and teacher personally identifiable information (PII) must be blocked from inclusion in executive reports.
3. **Audit Logging for Report Generation**:
   - Every report generation, filter execution, and CSV/JSON export action must automatically record an immutable audit log:
     ```json
     {
       "category": "platform_analytics",
       "action": "ANALYTICS_REPORT_EXPORTED",
       "actor": { "id": "usr_super_01", "ip": "192.168.1.10" },
       "details": "Exported executive_overview_summary report covering last_30_days",
       "metadata": { "format": "csv", "rowCount": 142 }
     }
     ```

## 6. Migration Roadmap from Frontend Adapters to Live Backend

When the backend reporting services are deployed, frontend migration will be seamless:
1. **Contract Parity**: The data shapes documented in `dashboard/lib/types/analytics.ts` match the proposed JSON API payloads.
2. **Adapter Swapping**:
   - Update `dashboard/lib/analytics/evaluator.ts` to call backend endpoints via `fetch()` with React Query / SWR caching.
   - Retain local evaluator selectors as fallback and offline testing modes.
3. **Data Provenance Toggle**:
   - The UI telemetry banner will automatically switch from `Demo Fixtures Simulated` to `Live Production Verified` based on the API response's `sourceProvenance.isSimulated` boolean.
