## 2. Server-Side Data Architecture & Privacy-Preserving Aggregations

### 2.1 The Differential Privacy & Data Minimization Imperative
Student data—specifically for K-12 minors—is protected under FERPA (US), COPPA (US), GDPR Article 9 (EU/UK), and regional child data protection frameworks.

The platform Super-Admin backend **must never** expose raw student tables or personal dossiers across tenant boundaries.

```
┌─────────────────────────────────────────────────────────────┐
│                 Tenant School Databases                     │
│  (Isolated DBs or Row-Level Security with tenant_id filter) │
│  - Raw students (name, DOB, address, medical, guardians)    │
│  - Raw admissions applications                              │
│  - Raw clearance records                                    │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               │ Scheduled Aggregation Worker / Event Streaming
                               ▼
┌─────────────────────────────────────────────────────────────┐
│             Tenant Macro-Aggregation Engine                 │
│  - Pre-computes count-only statistics                       │
│  - Strips all PII (names, emails, phones, addresses)        │
│  - Implements differential privacy thresholds (k-anonymity) │
│  - Suppresses small cells (e.g., if enrolled < 5 in class)  │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               │ Writes to
                               ▼
┌─────────────────────────────────────────────────────────────┐
│            Platform Oversight Aggregation Store             │
│  (Read-only table: `tenant_student_oversight_snapshots`)    │
│  - organization_id, campus_id, academic_session             │
│  - funnel_counts: inquiry, submitted, accepted, converted   │
│  - population_counts: enrolled, suspended, graduated, etc.  │
│  - data_quality_flags                                       │
└──────────────────────────────┬──────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────┐
│             Super-Admin REST / GraphQL API                  │
│       `GET /api/v1/superadmin/student-oversight`            │
│       - Requires Super-Admin RBAC                           │
│       - Emits cryptographic audit log entry on every query  │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 K-Anonymity & Small Cell Suppression
When aggregating student populations by division or campus, groups with fewer than 5 students (e.g. specialized accommodations) present re-identification risks.
- **Rule:** The aggregation worker must apply small-cell suppression (`< 5` reported as `< 5` or aggregated into general division totals) in any future drill-down endpoints.

## 3. Database Schema Blueprint (`tenant_student_oversight_snapshots`)

When database migrations are authorized, the following PostgreSQL schema should be provisioned:

```sql
-- PostgreSQL 16+ Table Definition for Pre-Aggregated Oversight Telemetry
CREATE TABLE IF NOT EXISTS platform_student_oversight_snapshots (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    campus_id UUID REFERENCES campuses(id) ON DELETE SET NULL,
    academic_session VARCHAR(32) NOT NULL, -- e.g., "2025/2026"
    
    -- Status & Sync Telemetry
    reporting_status VARCHAR(32) NOT NULL DEFAULT 'active_reporting',
    is_reporting BOOLEAN NOT NULL DEFAULT TRUE,
    last_reported_at TIMESTAMPTZ,
    
    -- Admissions Funnel Metrics
    inquiry_count INT NOT NULL DEFAULT 0,
    submitted_count INT NOT NULL DEFAULT 0,
    under_review_count INT NOT NULL DEFAULT 0,
    more_info_count INT NOT NULL DEFAULT 0,
    accepted_count INT NOT NULL DEFAULT 0,
    deferred_count INT NOT NULL DEFAULT 0,
    rejected_count INT NOT NULL DEFAULT 0,
    converted_count INT NOT NULL DEFAULT 0,
    conversion_rate_percentage NUMERIC(5,2) GENERATED ALWAYS AS (
        CASE WHEN submitted_count > 0 
             THEN ROUND((converted_count::NUMERIC / submitted_count::NUMERIC) * 100, 2)
             ELSE 0.00 END
    ) STORED,

    -- Population Lifecycle Breakdown
    enrolled_count INT NOT NULL DEFAULT 0,
    admitted_count INT NOT NULL DEFAULT 0,
    suspended_count INT NOT NULL DEFAULT 0,
    transferred_count INT NOT NULL DEFAULT 0,
    withdrawn_count INT NOT NULL DEFAULT 0,
    graduated_count INT NOT NULL DEFAULT 0,
    expelled_count INT NOT NULL DEFAULT 0,
    archived_count INT NOT NULL DEFAULT 0,

    -- Physical Campus Capacity
    student_capacity INT NOT NULL DEFAULT 0,
    capacity_utilization_percentage NUMERIC(5,2) GENERATED ALWAYS AS (
        CASE WHEN student_capacity > 0 
             THEN ROUND((enrolled_count::NUMERIC / student_capacity::NUMERIC) * 100, 2)
             ELSE 0.00 END
    ) STORED,

    -- Transfers & Clearance
    outgoing_transfers_total INT NOT NULL DEFAULT 0,
    outgoing_clearance_in_progress INT NOT NULL DEFAULT 0,
    outgoing_cleared INT NOT NULL DEFAULT 0,
    outgoing_approved INT NOT NULL DEFAULT 0,
    outgoing_completed INT NOT NULL DEFAULT 0,
    outgoing_cancelled INT NOT NULL DEFAULT 0,
    incoming_transfers_total INT NOT NULL DEFAULT 0,
    incoming_under_review INT NOT NULL DEFAULT 0,
    incoming_approved INT NOT NULL DEFAULT 0,
    incoming_enrolled INT NOT NULL DEFAULT 0,

    -- JSONB Stores for Flexible Aggregates
    clearance_bottlenecks_json JSONB DEFAULT '[]'::jsonb,
    grade_divisions_json JSONB DEFAULT '[]'::jsonb,
    data_quality_issues_json JSONB DEFAULT '[]'::jsonb,

    -- Audit Metadata
    created_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT uq_org_campus_session UNIQUE(organization_id, campus_id, academic_session)
);

CREATE INDEX idx_student_oversight_org ON platform_student_oversight_snapshots(organization_id);
CREATE INDEX idx_student_oversight_session ON platform_student_oversight_snapshots(academic_session);
CREATE INDEX idx_student_oversight_reporting ON platform_student_oversight_snapshots(is_reporting, reporting_status);
```

## 4. API Endpoints Specification

### 4.1 Global Aggregated Oversight
- **Route:** `GET /api/v1/superadmin/student-oversight`
- **Authorization:** `SUPER_ADMIN` or `PLATFORM_AUDITOR` with permission `platform.oversight.read`.
- **Query Parameters:**
  - `organizationId` (UUID | 'ALL')
  - `campusId` (UUID | 'ALL')

## 5. Security, Multi-Tenant Isolation & Audit Logging

### 5.1 Multi-Tenant Isolation Enforcement
1. **Separation of Tenant Queries:** Tenant school dashboards query `tenant_id = req.user.tenantId`. Super-Admin endpoints read from the pre-aggregated `platform_student_oversight_snapshots` table. Under no circumstances should Super-Admin endpoints execute un-scoped `SELECT * FROM students`.
2. **Preventing Cross-Tenant Leakage:** Any endpoint accepting an `organizationId` query parameter must validate against the central `organizations` catalog. Query results are strictly grouped by `organization_id`.

### 5.2 Mandatory Audit Logging
Every access to student oversight telemetry must emit an `AuditEvent` with:
- `actorId`, `actorName`, `actorRole`
- `action`: `STUDENT_OVERSIGHT_ACCESSED` or `STUDENT_OVERSIGHT_EXPORTED`
- `targetResource`: `organizationId` or `ALL_ORGANIZATIONS`
- `filterParameters`: JSON snapshot of search, session, and campus filters
- `timestamp`: ISO-8601 UTC timestamp
- `clientIp`, `userAgent`

## 6. Retention, Archival & Purging Policies

1. **Active Session Snapshots:** Refreshed daily via cron worker for active sessions.
2. **Historical Retention:** End-of-session snapshots are locked as immutable records for regulatory auditing (retained for 7 years).
3. **Tenant Decommissioning & Right to be Forgotten:**
   - If an organization is archived/decommissioned (`archived`), historical aggregate snapshots may be retained for platform financial and capacity reporting.
   - If a tenant requests formal data deletion (GDPR Article 17), all underlying tenant-side databases are purged, and platform snapshots are marked `reporting_status = 'purged'` with student counters anonymized.

---

## 7. Performance & High-Throughput Strategy for Large Populations

For school districts or networks with 100,000+ students:
1. **No Real-Time `COUNT(*)` on Students:** Aggregation queries must **never** perform runtime table scans across millions of student rows upon Super-Admin dashboard load.
2. **Materialized Aggregations:** Telemetry is written asynchronously to `platform_student_oversight_snapshots` via event handlers (`StudentEnrolledEvent`, `ApplicationSubmittedEvent`, `TransferCompletedEvent`).
3. **Redis Read-Through Caching:** Cached with a 15-minute TTL (`student_oversight:${session}:${orgId}`) and invalidated on sync events.
