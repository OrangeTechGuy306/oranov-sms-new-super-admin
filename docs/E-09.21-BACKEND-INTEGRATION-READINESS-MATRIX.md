## 1. Executive Summary & Architecture Paradigm

The Super-Admin Dashboard (`dashboard/`) has been completely consolidated and quality-certified in Phase E-09.21. Currently, all 28 routes and 22 governance workspaces operate on deterministic, type-safe frontend fixtures, mock stores, and client-side lifecycle evaluators.

This document establishes the **authoritative backend integration contract** for future engineering phases. It details every governance module, current mock sources, proposed backend microservices and REST/RPC endpoints, JSON schema request/response contracts, query parameters, sorting/pagination standards, multi-tenant scope isolation, and error resilience specifications.

### 1.1 Non-Negotiable Integration Rules for Future Backend Teams
1. **Zero Frontend Regressions:** The UI component schemas, enums, and UX state machines developed across Phases E-09.5 through E-09.21 represent the gold-standard interface. Backend endpoints must map 1:1 with these existing TypeScript contracts or provide clean adapter bridges in `lib/adapters/`.
2. **Multi-Tenant Data Privacy (Zero-PII Exposure):** Oversight workspaces (`/student-oversight`, `/academic-oversight`, `/examination-governance`) MUST NOT transmit student names, national IDs, contact emails, phone numbers, or residential addresses to the Super-Admin dashboard. The backend must strictly aggregate statistics, ratios, and anonymized cohort distribution metrics.
3. **Multi-Factor & Idempotency Requirements:** All write actions modifying school states (suspension, archival, tenant provisioning, plan alteration, database migration, webhook regeneration) must accept idempotency keys (`Idempotency-Key` header) and require authenticated Super-Admin session tokens with high-privilege IAM roles (`SUPER_ADMIN`, `SYSTEM_OPERATOR`).

## 2. Universal API Standards & Conventions

All endpoints documented herein follow standard RESTful conventions:

```http
GET    /api/v1/governance/<resource>         - Paginated query with filtering and sorting
POST   /api/v1/governance/<resource>         - Creation / Provisioning (Idempotent)
GET    /api/v1/governance/<resource>/:id     - Entity detail retrieval
PATCH  /api/v1/governance/<resource>/:id     - Partial field update / mutation
POST   /api/v1/governance/<resource>/:id/<action> - State machine transitions (activate, suspend, etc.)
```

### 2.1 Standard Paginated Envelope
```json
{
  "success": true,
  "data": [ /* Array of records */ ],
  "pagination": {
    "page": 1,
    "limit": 25,
    "totalRecords": 142,

```

  "success": false,

## 4. Deep-Dive Specification by Governance Domain

### 4.1 Organizations & Tenant Lifecycle Management
- **Routes:** `/organizations`, `/organizations/new`, `/organizations/[organizationId]`, `/organizations/[organizationId]/subscription`
- **Frontend Source:** `lib/mock-data.ts`, `lib/modules/registry-data.ts`, `lib/lifecycle/evaluator.ts`
- **Backend Service:** `organization-service`

#### Endpoints
```http
GET    /api/v1/governance/organizations
       Query: page=1&limit=25&search=&status=active|provisioning|suspended|archived&tier=tier_essential|tier_growth|tier_enterprise&state=&lga=&sort=name:asc
       Response: { organizations: Organization[], total: number }

POST   /api/v1/governance/organizations
       Header: Idempotency-Key: <uuid>
       Payload: {
         name: string,
         code: string,
         subdomain: string,
         tier: 'tier_essential' | 'tier_growth' | 'tier_enterprise',
         adminEmail: string,
         adminName: string,
         state: string,
         lga: string,
         campusCount: number,
         allocatedStudentQuota: number,
         modules: string[]
       }
       Response: { organization: Organization, initialCredentials: { temporaryPassword: string } }

GET    /api/v1/governance/organizations/:id
       Response: { organization: OrganizationDetail, campuses: Campus[], subscription: SubscriptionSummary }

POST   /api/v1/governance/organizations/:id/transition
       Payload: { action: 'suspend' | 'activate' | 'archive' | 'restore', reason: string, scheduledDate?: string }
       Response: { organization: Organization, auditLogId: string }

PUT    /api/v1/governance/organizations/:id/modules
       Payload: { enabledModules: string[], disabledModules: string[], notes: string }
       Response: { organizationId: string, updatedModules: ModuleActivationRecord[] }
```

#### State Transition Logic (Migrating to Backend)
Currently validated in `lib/lifecycle/evaluator.ts`. The backend must enforce:
- `active` $\rightarrow$ `suspended` (with reason required)
- `suspended` $\rightarrow$ `active` or `archived`
- `archived` $\rightarrow$ `inactive` (strictly cannot transition directly to `active`)
- `provisioning` $\rightarrow$ `active` upon initial admin verification

#### Security & Privacy Contract
- **Contract Rule PII-01:** Response bodies for `/api/v1/governance/student-oversight` MUST NOT contain individual student records, guardian identifiers, phone numbers, or dates of birth.
- **Contract Rule CBT-02:** Concurrency metrics must be pushed from tenant redis instances into time-series buckets; Super-Admin reads cached window values.

## 5. Security & Authentication Requirements

### 5.1 Super-Admin Session Token Standard
Requests from `dashboard/` to backend services will supply an HTTP Bearer JWT:
```http
Authorization: Bearer eyJhbGciOiJFUzI1NiIsInR5cCI6IkpXVCJ9...
```
The claims payload will contain:
```json
{
  "sub": "usr_superadmin_018a42f...",
  "iss": "https://auth.sms-platform.internal",
  "aud": "https://api.sms-platform.internal/governance",
  "scope": "platform:super_admin",
  "roles": ["SUPER_ADMIN"],
  "permissions": [
    "orgs:read", "orgs:write", "orgs:lifecycle",
    "billing:read", "billing:write", "billing:refund",
    "iam:read", "iam:write",
    "audit:read", "audit:export",
    "governance:purge"
  ],
  "exp": 1792700000
}
```

### 5.2 CSV Formula Injection Shield
The frontend utility `lib/utils/csv-export.ts` sanitizes all client exports. However, backend export generators (`GET /api/v1/governance/.../export.csv`) must ALSO prepend single quotes (`'`) to any cell values starting with `=, +, -, @, \t, \r` to ensure defense-in-depth against malicious CSV payloads entered into school or student metadata.

## 6. Adapter Migration Architecture (`lib/adapters/`)

When backend services become available in Phase E-09.22+, `dashboard/` should introduce thin adapter modules under `lib/adapters/` that translate HTTP responses into the established TypeScript interfaces without requiring UI refactoring:

```typescript
// lib/adapters/organization-adapter.ts (Future Pattern)
import { Organization } from '@/lib/types';
import { BackendOrganizationDto } from './dtos';

export function adaptOrganizationDto(dto: BackendOrganizationDto): Organization {
  return {
    id: dto.org_id,
    name: dto.legal_name,
    code: dto.identifier_code,
    status: dto.lifecycle_state,
    tier: dto.subscription_tier,
    studentCount: dto.stats.enrolled_students,
    campusCount: dto.stats.campuses_count,
    state: dto.geo.state,
    lga: dto.geo.lga,
    joinedDate: dto.created_at,
    contactEmail: dto.billing_contact.email,
  };
}
```
