# PHASE E-09.10: BACKEND READINESS & CONTRACT SPECIFICATIONS
## Examinations, Computer-Based Testing (CBT), Timetabling & Assessment Governance

---

### Executive Confirmation

**NO BACKEND INFRASTRUCTURE, DATABASE SCHEMA, SERVER ENDPOINT, OR PRODUCTION API INTEGRATION WAS IMPLEMENTED IN THIS PHASE.**

All frontend components, evaluation engines, metrics, and views in `dashboard/` operate strictly against typed contracts and deterministic mock fixtures. This document defines the engineering specifications, relational schemas, database constraints, API endpoints, Row-Level Security (RLS) policies, and performance criteria required for future backend implementation.

---

## 1. Required API Endpoints for Platform Examination Governance

To transition the Super-Admin examination governance workspace from development fixtures to production APIs, the future backend must expose the following platform-level authenticated endpoints:

```
GET /api/v1/superadmin/examination-governance
GET /api/v1/superadmin/examination-governance/summary
GET /api/v1/superadmin/examination-governance/organizations/:organizationId
GET /api/v1/superadmin/examination-governance/cbt-telemetry
GET /api/v1/superadmin/examination-governance/question-banks/summary
GET /api/v1/superadmin/examination-governance/timetable-conflicts
GET /api/v1/superadmin/examination-governance/export
```

### 1.1 Global Examination Governance Summary
- **Endpoint:** `GET /api/v1/superadmin/examination-governance/summary`
- **RBAC Guard:** `superadmin.examinations.view`
- **Query Parameters:**
  - `academicPeriod?: string`
  - `deliveryMode?: 'PAPER_BASED' | 'CBT_HYBRID' | 'CBT_FULL'`
  - `readinessLevel?: 'ready' | 'partially_ready' | 'not_ready' | 'not_applicable'`
  - `startDate?: string` (ISO 8601 YYYY-MM-DD)
  - `endDate?: string` (ISO 8601 YYYY-MM-DD)
- **Response Schema:** Matches `AggregatedExamGovernanceMetrics` (total organizations, ready organizations, scheduled assessments, in-progress tests, marks entry, moderation, awaiting publication, published, cancelled, total CBT attempts, completed attempts, active CBT exceptions, question bank count, critical timetable clashes, warning clashes).

### 1.2 Tenant-Scoped Examination Configuration Query
- **Endpoint:** `GET /api/v1/superadmin/examination-governance/organizations/:organizationId`
- **RBAC Guard:** `superadmin.examinations.view`
- **Response Schema:** Matches `OrganizationExamGovernance` (organization metadata, campuses, active exam period, components, CBT telemetry, question bank metadata, timetable and conflict summary, grading configuration, results publication readiness, data quality issues, and 8-point canonical readiness evaluation).

### 1.3 Aggregate CSV Export
- **Endpoint:** `GET /api/v1/superadmin/examination-governance/export`
- **Format:** `text/csv` (RFC 4180 with mandatory formula injection neutralization)
- **Filters:** All standard filter parameters supported by the frontend.
- **Privacy Enforcement:** Under no circumstances may student names, admission numbers, individual scores, or question texts be returned.

## 2. Relational Schema & Persistence Requirements

Future backend implementations should establish or interface with the following relational tables:

### 2.1 Examination Series & Assessment Components (`exam_series`, `assessment_components`)
```sql
CREATE TABLE exam_series (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    campus_id UUID REFERENCES campuses(id) ON DELETE CASCADE,
    session_id UUID NOT NULL REFERENCES academic_sessions(id) ON DELETE RESTRICT,
    period_id UUID NOT NULL REFERENCES academic_periods(id) ON DELETE RESTRICT,
    name VARCHAR(150) NOT NULL, -- e.g. "2026/2027 First Term Examinations"
    category VARCHAR(50) NOT NULL DEFAULT 'STANDARD', -- STANDARD, MOCK, MIDTERM, ENTRANCE
    delivery_mode VARCHAR(30) NOT NULL DEFAULT 'PAPER_BASED', -- PAPER_BASED, CBT_HYBRID, CBT_FULL
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    status VARCHAR(30) NOT NULL DEFAULT 'DRAFT', -- DRAFT, SCHEDULED, IN_PROGRESS, CONCLUDED, PUBLISHED, CANCELLED
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT chk_exam_series_dates CHECK (start_date <= end_date)
);

CREATE TABLE assessment_components (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    series_id UUID NOT NULL REFERENCES exam_series(id) ON DELETE CASCADE,
    subject_id UUID NOT NULL REFERENCES subjects(id) ON DELETE RESTRICT,
    class_id UUID NOT NULL REFERENCES classes(id) ON DELETE RESTRICT,
    title VARCHAR(150) NOT NULL, -- e.g. "Physics Paper 1 - Multiple Choice"
    type VARCHAR(40) NOT NULL, -- CONTINUOUS_ASSESSMENT, MID_TERM, TERMINAL_EXAM, PRACTICAL, MOCK
    delivery_mode VARCHAR(30) NOT NULL DEFAULT 'PAPER_BASED',
    max_marks NUMERIC(5, 2) NOT NULL DEFAULT 100.00,
    weight_percentage NUMERIC(5, 2) NOT NULL, -- e.g. 30.00 for 30%
    duration_minutes INTEGER NOT NULL DEFAULT 60,
    status VARCHAR(30) NOT NULL DEFAULT 'DRAFT', -- DRAFT, SCHEDULED, IN_PROGRESS, MARKS_ENTRY, MODERATION, AWAITING_PUBLICATION, PUBLISHED, CANCELLED
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT chk_weight_positive CHECK (weight_percentage >= 0 AND weight_percentage <= 100)
);
```

### 2.2 Question Bank & Cognitive Taxonomy (`question_banks`, `questions`, `question_blueprints`)
```sql
CREATE TABLE question_banks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    subject_id UUID NOT NULL REFERENCES subjects(id) ON DELETE RESTRICT,
    name VARCHAR(150) NOT NULL,
    description TEXT,
    created_by UUID NOT NULL REFERENCES users(id),
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

);

CREATE TABLE questions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    bank_id UUID NOT NULL REFERENCES question_banks(id) ON DELETE CASCADE,
    question_type VARCHAR(40) NOT NULL, -- MULTIPLE_CHOICE, MULTIPLE_RESPONSE, TRUE_FALSE, FILL_IN_BLANK, SHORT_ANSWER, ESSAY, MATCHING, ORDERING
    difficulty VARCHAR(20) NOT NULL DEFAULT 'MEDIUM', -- EASY, MEDIUM, HARD, HIGHER_ORDER
    status VARCHAR(30) NOT NULL DEFAULT 'DRAFT', -- DRAFT, IN_REVIEW, APPROVED, REJECTED, ARCHIVED
    marks NUMERIC(4, 2) NOT NULL DEFAULT 1.00,
    content_encrypted BYTEA NOT NULL, -- Encrypted question text and options
    solution_encrypted BYTEA NOT NULL, -- Encrypted solution / answer key
    topic_tag VARCHAR(100),
    review_notes TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 2.3 Examination Timetable & Conflict Engine (`exam_timetable_slots`)
```sql
CREATE TABLE exam_timetable_slots (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    campus_id UUID NOT NULL REFERENCES campuses(id) ON DELETE CASCADE,
    series_id UUID NOT NULL REFERENCES exam_series(id) ON DELETE CASCADE,
    component_id UUID NOT NULL REFERENCES assessment_components(id) ON DELETE CASCADE,
    exam_date DATE NOT NULL,
    start_time TIME NOT NULL,
    end_time TIME NOT NULL,
    room_id UUID NOT NULL REFERENCES rooms(id) ON DELETE RESTRICT,
    invigilator_id UUID REFERENCES users(id) ON DELETE SET NULL,
    candidate_count INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT chk_exam_slot_time CHECK (start_time < end_time)
);

-- Fast spatial/interval index to detect room clashing
CREATE INDEX idx_exam_room_conflict 
ON exam_timetable_slots(tenant_id, campus_id, room_id, exam_date, start_time, end_time);

-- Fast index to detect invigilator double-booking
CREATE INDEX idx_exam_invigilator_conflict 
ON exam_timetable_slots(tenant_id, invigilator_id, exam_date, start_time, end_time) 
WHERE invigilator_id IS NOT NULL;
```

### 2.4 CBT Examination Sessions & Telemetry (`cbt_sessions`, `cbt_telemetry_events`)
```sql
CREATE TABLE cbt_sessions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    component_id UUID NOT NULL REFERENCES assessment_components(id) ON DELETE CASCADE,
    student_id UUID NOT NULL REFERENCES students(id) ON DELETE CASCADE,
    start_time TIMESTAMPTZ,
    end_time TIMESTAMPTZ,
    scheduled_duration_minutes INTEGER NOT NULL,
    extended_minutes INTEGER NOT NULL DEFAULT 0,
    status VARCHAR(30) NOT NULL DEFAULT 'NOT_STARTED', -- NOT_STARTED, IN_PROGRESS, SUBMITTED, TIMED_OUT, DISQUALIFIED
    ip_address INET,
    user_agent TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uq_cbt_student_exam UNIQUE (component_id, student_id)

CREATE TABLE cbt_telemetry_events (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    session_id UUID NOT NULL REFERENCES cbt_sessions(id) ON DELETE CASCADE,
    event_type VARCHAR(40) NOT NULL, -- TAB_BLUR, FULLSCREEN_EXIT, CONNECTION_LOST, TIME_EXTENDED, FORCE_SUBMIT
    occurred_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    metadata JSONB
);
```

## 3. Row-Level Security (RLS) & Multi-Tenant Isolation

1. **Tenant Isolation:** Every table MUST have `tenant_id` and strict PostgreSQL RLS policies enabled. Tenant users can only read and write data where `tenant_id = current_setting('app.current_tenant_id')::uuid`.
2. **Super-Admin Governance:** Super-Admin users execute via a platform role that bypasses tenant filters *only* via aggregated SQL rollup views (e.g., `v_superadmin_exam_governance`). Super-Admin roles must never query raw `cbt_sessions` or `questions` directly.
3. **Question Content Encryption:** Question text, multiple-choice options, and solution keys must be stored in encrypted columns (`content_encrypted`, `solution_encrypted`) using tenant-specific KMS keys. Super-Admin access never receives decryption keys.

---

## 4. Aggregate Rollup & Data Freshness Strategy

For large-scale multi-tenant operations (e.g., 500+ schools, 250,000+ candidates), calculating real-time CBT sessions and timetable clashes on every dashboard request would degrade database performance. The backend must implement:

1. **Materialized Rollup View (`mat_exam_governance_summary`):** Refreshed every 15 minutes or triggered asynchronously on major state transitions (e.g., exam series published, report cards released).
2. **Redis Real-Time Telemetry Cache:** CBT live metrics (active sessions, exceptions) should be tracked in a Redis sorted set / counter pipeline with a 60-second TTL.
3. **Conflict Detection Worker:** Timetable clash detection should execute as a background BullMQ / Celery worker whenever a slot is created or updated, writing detected conflicts to an `exam_conflicts` cache table.

---

## 5. Unresolved Architecture Questions & Recommendations

1. **AI Automated Proctoring Requirements:** If webcam facial recognition or audio anomaly detection is required in future phases, an external WebRTC media server (e.g., Janus / LiveKit) and consent compliance pipeline (GDPR / NDPR) will be needed. The current tenant frontend does not possess these components.
2. **Mass PDF Report Card Generation:** Rendering 50,000 terminal report cards with QR codes requires an asynchronous PDF queue (e.g., Puppeteer / Gotenberg) to prevent thread exhaustion on tenant web instances.
3. **Offline Sync Conflict Resolution:** When an offline candidate reconnects and submits buffered responses that conflict with a server-side timeout auto-submission, clear precedence rules must be established (e.g., latest client timestamp accepted within a 15-minute grace window).
